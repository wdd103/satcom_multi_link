# 飞机、传感器与机体遮挡

网页新增「飞机与传感器」。示例项目已经导入用户提供的 `scenario_zhedang.sc` 中 AC1 的飞机、模型和 RoofAntennaMask 传感器配置；原始运行目录中的场景文件保持不变。

## 网页操作

1. 可输入本机已有 `.sc` 场景路径，点击「读取飞机及传感器配置」。相关 `.ac`、`.ac3`、`.sn`、`.sn3`、模型和 `.bmsk` 复制到项目 `assets`，配置进入草稿。
2. 选择源飞机，输入 `AC2, AC3, AC4` 等新 ID，点击「批量复制飞机及链路」。同时复制航迹、飞机模型、传感器、收发机、天线及飞机上/下行链路。每架可按序叠加经纬度、高度偏移；全部为零表示航迹重合。单次最多新增 100 架。
3. 每架飞机可以选择默认可见性传感器。每个传感器可以编辑安装位置、固定指向四元数、圆锥半角，上传或选择 `.bmsk`，并切换「使用遮挡文件」。安装坐标采用 STK 机体系，单位米。
4. 点击顶部「保存」，验证通过后运行。链路也可以通过 `mask_sensor_id` 覆盖飞机默认传感器。

「将源飞机传感器同步到全部飞机」会替换其他飞机的传感器草稿，适用于相同机体、缩放和安装位置。新建传感器默认关闭遮挡文件。关闭「使用遮挡文件」保留传感器视场约束；如需完全取消传感器约束，将飞机默认可见性传感器设为空并清除链路覆盖。

## 导入的原始设置

- 飞机模型：STK `Air/airliner.mdl`，缩放 1，模型偏移为零。
- 原生姿态：保留源飞机的 `AircraftZDownAtt` 配置。
- 传感器：`RoofAntennaMask`，SimpleCone 半角 90°。
- 安装位置：`(0, 0, -1.37) m`。
- 固定指向四元数：`(qx,qy,qz,qw) ≈ (0,1,0,0)`。
- 遮挡文件：源 `RoofAntennaMask.bmsk`，启用原生 SensorAzElMask 约束。

当前导入支持固定位置、固定指向、SimpleCone 传感器；不支持的原生类型会报错。原生模板保存其他飞机设置，但本功能没有从经纬高航迹推导真实爬升俯仰或转弯横滚。要研究姿态变化导致的遮挡，还需要提供正确的姿态历程。

## 计算与输出

飞机链路在每个采样时刻同时检查原有几何可见性、选定传感器对该卫星的 Access，以及原生通信链路 Access。传感器 Access 包含视场和启用的机体遮挡约束。地面链路沿用原有几何约束。

下行干扰源也必须通过接收飞机选定传感器的可见性检查；被遮挡的非服务卫星不会计入聚合干扰。接收方向图仍按当前候选服务卫星指向计算。

新增 `aircraft_sensor_visibility.csv`，记录几何可见性、传感器可见性及其交集。`link_budget.csv` 增加 `geometric_access`、`mask_sensor_id`、`sensor_access`，便于区分几何不可见和传感器阻挡。场景包包含模型、模板、遮挡文件；manifest 记录配置。

`.bmsk` 是已有机体几何在指定传感器安装位置和坐标系下的遮挡结果。本功能负责导入、选择、批量复用和运行时应用，不负责从新模型自动生成遮挡文件。修改机体、模型缩放、模型偏移或传感器安装/指向后，应在 STK 重新生成相匹配的文件。

## 验证

Python 单元测试覆盖模板解析、批量复制依赖、文件导入、上传和验证；前端测试覆盖开关、安装点编辑和保存。`scripts/probe_fleet_masks.py` 用独立 STK 实例验证两架飞机、两个卫星、原生传感器加载、72 条预算及 24 条传感器记录，并检查服务和干扰过滤一致性。该次轨迹未出现「几何可见但被传感器挡住」的样本，因此不作为具体机体遮挡边界的精度验证。
